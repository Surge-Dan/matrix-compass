# Matrix Compass 本地创作者经营实验室设计规格

日期：2026-07-30

状态：待用户最终审核

目标版本：v1 本地正式版与公网演示版

## 1. 产品结论

Matrix Compass 从“多平台自动监控看板”调整为“本地优先的个人创作者经营实验室”。

产品不依赖高风险的网页抓取或难以长期获得的多平台数据权限。用户通过表单或 XLSX/CSV 导入内容、表现、收入与成本数据，系统把每篇内容视为一次可验证的经营实验，回答四个问题：

1. 今天最值得处理什么；
2. 哪类内容表现更好，证据有多强；
3. 收入来自哪里，投入产出如何；
4. 下一篇只改变什么变量进行验证。

表格、日历、数据分析和收入管理都保留，但它们不是孤立的数据表，而是同一份内容主记录的不同视图。

## 2. 目标用户与使用边界

### 2.1 目标用户

- 单个个人创作者；
- 同时经营公众号、小红书、抖音、快手、B 站或其他平台的多个账号；
- 当前使用飞书多维表、Excel 或零散文档管理发布与收入；
- 需要在电脑完成深度管理，并在同一局域网用手机快速查看、录入和补数据；
- 重视个人内容、客户和收入数据的本地隐私。

### 2.2 v1 非目标

- 不自动抓取平台网页、Cookie 或模拟登录；
- 不承诺接入四个平台的完整官方数据 API；
- 不做多成员权限、任务分配和团队审批；
- 不做跨互联网远程访问和双向云同步；
- 不做自动发布内容；
- 不替代正式会计、报税或发票系统；
- 不让 AI 自动修改原始数据、财务记录或已验证策略。

## 3. 产品原则

### 3.1 一份主数据，多种工作视图

内容、排期、指标快照、收入、成本、复盘和策略证据通过稳定 ID 关联。用户修改一次，表格、日历、仪表盘和详情页同步更新。

### 3.2 渐进式录入

创建内容时只要求五项：内容主题、平台与账号、内容类型、当前阶段、计划日期。发布表现、收入、成本和复盘在生命周期后续阶段补充。

### 3.3 原始数据与推导数据分离

用户输入和文件导入的数据作为原始事实保存；互动率、转化率、ROI、表现指数和策略建议属于可重算的派生结果，不回写覆盖原始数据。

### 3.4 证据边界可见

任何分析都显示比较基线、统计窗口、样本数、缺失情况和证据等级。数据不足时明确显示“暂不能判断”，不把相关性表述为因果。

### 3.5 零静默丢数

未映射字段、冲突记录、解析失败行和未归因收入都必须保留并可追溯，不能静默删除、覆盖或强行匹配。

## 4. 信息架构

### 4.1 今日驾驶舱

首页围绕行动，而不是堆叠全部图表：

- 今天计划创作或发布的内容；
- 已发布但到期未补录的 T+1、T+3、T+7 数据；
- 待复盘内容；
- 待关联收入；
- 即将到期或逾期的待收款；
- 本周值得执行的下一项内容实验。

首页摘要指标包括本月发布数、待复盘数、净收入、待收款和单位小时收益。

### 4.2 内容实验

内容数据支持以下视图：

- 表格：批量筛选、排序、分组、编辑和导出；
- 流程看板：灵感、假设、大纲、制作、待发布、已发布、待复盘、已归档；
- 详情：内容假设、执行投入、数据快照、收入、复盘和策略证据；
- 保存视图：允许保存常用筛选与排序，但 v1 不实现飞书级任意视图搭建器。

### 4.3 发布日历

- 月、周和列表视图；
- 展示计划制作、计划发布、实际发布、数据补录、复盘和收入对账事件；
- 同一内容的生命周期事件使用统一颜色体系；
- 支持拖动调整计划日期，实际发布日期不能被拖动误改；
- 日历与内容表使用同一份记录，不重复维护。

### 4.4 数据复盘

- 总览趋势；
- 账号与平台内基线比较；
- 内容类型、形式、主题、标题结构、发布时间和 CTA 等维度分析；
- 单篇内容诊断；
- 下一轮实验建议；
- 分析完整度和证据等级。

### 4.5 收入与 ROI

- 收入流水；
- 成本与工时；
- 确认、开票、待收款、已到账和逾期状态；
- 内容归因与未归因队列；
- 平台、账号、收入类型和内容类型分析；
- 现金利润、现金 ROI、经济 ROI、单位小时收益和千次消费收入；
- 收入构成、平台净利润、结算账龄、收入趋势、高收入内容榜和内容机会象限。

### 4.6 策略资产

- 观察；
- 可验证假设；
- 已验证策略；
- 稳定策略；
- 支持案例、反例、适用范围、失效条件和下一次复验时间。

### 4.7 导入与备份

- 表单录入；
- 飞书多维表导出的 XLSX/CSV；
- Matrix Compass 标准模板；
- 任意表格的交互式字段映射；
- 导入预览、校验、撤销和错误报告；
- 自动备份、手动备份和恢复预演。

## 5. 核心业务流程

### 5.1 内容经营闭环

1. 用户创建内容记录；
2. 可选填写受众、痛点、核心承诺和待验证假设；
3. 在日历安排制作与发布；
4. 记录实际发布时间和链接；
5. 在 T+1、T+3、T+7 保存表现快照；
6. 关联收入、现金成本和制作工时；
7. 系统生成描述性和诊断性摘要；
8. 用户完成复盘并提出下一项单变量实验；
9. 可复用结论进入策略资产，随新证据升级或降级。

### 5.2 日常最小操作

- 新灵感：30 秒内完成五项基础字段；
- 发布后：只显示该平台相关指标，不要求填写不存在的数据；
- 收入发生：可先记为未归因，后续再分配；
- 每周复盘：系统聚合到期任务和可信信号，不要求逐表查找。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | 是 | 本地主键 |
| `platform` | enum/string | 是 | 公众号、小红书、抖音、快手、B站、其他 |
| `name` | string | 是 | 账号名称 |
| `positioning` | string | 否 | 账号定位 |
| `cadence` | string | 否 | 发布规则，如每周两更 |
| `topic_directions` | string[] | 否 | 选题方向 |
| `monetization_paths` | string[] | 否 | 流量广告、商单、私域、佣金等 |
| `current_followers` | integer | 否 | 最近一次手动记录的粉丝数 |
| `active` | boolean | 是 | 是否继续经营 |

| `account_id` | UUID | 是 | 关联账号，平台由账号确定 |
| `content_type` | string | 是 | 工作、生活、学习等可配置分类 |
| `format` | string | 否 | 图文、文章、短视频、直播等 |
| `stage` | enum | 是 | 灵感到归档的生命周期阶段 |
| `planned_at` | datetime | 是 | 计划日期 |
| `published_at` | datetime | 否 | 实际发布日期 |
| `url` | string | 否 | 发布链接 |
| `audience` | string | 否 | 目标受众 |
| `user_problem` | string | 否 | 用户问题或使用场景 |
| `core_promise` | string | 否 | 内容对用户的核心承诺 |

### 6.3 `schedule_events`

- 关联内容；
- 类型：制作、发布、数据补录、复盘、收入对账、自定义；
- 计划开始与结束时间；
- 完成时间；
- 是否由生命周期规则自动生成；
- 用户调整后的来源记录。

### 6.4 `metric_snapshots`

每个快照保存 `captured_at` 和 `window_label`，例如 T+1、T+3、T+7。新快照不能覆盖旧快照。

通用原始字段：

- `impressions`：曝光；
- `consumption_count`：阅读或播放；
- `likes`、`comments`、`saves`、`shares`；
- `follower_gain`；
- `leads`、`orders`；
- `completion_rate`、`average_watch_seconds`；
- `platform_payload`：保留平台特有字段及原字段名；
- `source`：manual、import；
- `source_batch_id`：来源导入批次。

表单按平台展示字段：

- 公众号：送达、阅读、分享、在看、点赞、新增关注；
- 小红书：曝光、观看、点赞、收藏、评论、分享、新增关注；
- 抖音与快手：曝光、播放、点赞、评论、收藏、分享、新增关注、完播率、平均观看时长；
- 其他平台使用通用字段模板。

### 6.5 `income_entries`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | 是 | 收入流水主键 |
| `account_id` | UUID | 否 | 可先不指定账号 |
| `income_type` | string | 是 | 流量广告、合作约稿、商单、佣金、直播、产品、服务、其他 |
| `client_name` | string | 否 | 客户或品牌 |
| `gross_amount` | decimal | 是 | 确认金额 |
| `platform_fee` | decimal | 是 | 默认 0 |
| `tax_amount` | decimal | 是 | 默认 0 |
| `currency` | string | 是 | v1 默认 CNY |
| `status` | enum | 是 | expected、confirmed、invoiced、received、overdue、cancelled |
| `confirmed_at` | date | 否 | 收入确认日期 |
| `expected_at` | date | 否 | 预计到账日期 |
| `received_at` | date | 否 | 实际到账日期 |
| `review_highlight` | text | 否 | 复盘亮点 |
| `review_problem` | text | 否 | 复盘问题 |
| `optimization_direction` | text | 否 | 优化方向 |

金额使用定点十进制或最小货币单位整数保存，禁止二进制浮点累计误差。

### 6.6 `cost_entries`

- 关联内容或项目；
- 类型：外包、投流、工具、素材、设备、差旅、平台费、其他；
- 金额和日期；
- 制作工时单独记录；
- 用户可设置用于经济 ROI 的个人时薪，默认不设置。

### 6.7 `income_attributions`

- 一笔收入可分配给零篇、一篇或多篇内容；
- 一篇内容可以关联多笔收入；
- 字段包括 `income_id`、`content_id`、`allocated_net_amount`、`attribution_type`、`confidence`、`note`；
- `attribution_type`：direct、assisted、bundle；
- `confidence`：high、medium、low；
- 同一收入的分配金额总和不能超过该笔净收入；
- 未分配部分始终显示为“未归因”，不能自动塞给最后一篇内容。

### 6.8 `reviews`、`strategy_rules` 与 `strategy_evidence`

复盘保存：结果摘要、表现亮点、主要问题、解释性假设、下一步动作、下一实验、完成日期。

策略规则保存：规则文本、适用平台、账号、类型、证据等级、状态、创建与复验日期。

证据关系保存：关联内容、支持或反例、观察窗口、影响指标和备注。

### 6.9 导入与审计

- `import_batches`：文件指纹、工作表、导入时间、映射版本、行数、状态、备份路径；
- `import_rows`：原始行号、原始字段、解析结果、错误、重复候选和最终动作；
- `audit_log`：关键新增、修改、删除、合并、恢复和移动端写入事件；
- `paired_devices`：配对设备、授权时间、最后使用时间和撤销状态。

## 7. 指标定义

### 7.1 基础指标

- 净收入 = 确认金额 − 平台费 − 税费；
- 现金利润 = 已归因净收入 − 已归因现金成本；
- 现金 ROI = 现金利润 ÷ 已归因现金成本；
- 经济成本 = 现金成本 + 工时 × 用户设置的时薪；
- 经济 ROI =（已归因净收入 − 经济成本）÷ 经济成本；
- 单位小时收益 = 现金利润 ÷ 制作工时；
- 千次消费收入 = 已归因净收入 ÷ 阅读或播放 × 1000；
- 互动数 = 点赞 + 评论 + 收藏 + 分享；
- 互动率优先使用曝光作为分母；曝光缺失时使用阅读或播放，并明确显示分母口径；
- 涨粉转化率 = 新增关注 ÷ 阅读或播放。

分母为零或缺失时返回空值并显示“无法计算”，不能显示无穷大或伪造 0%。

### 7.2 内容表现指数

内容只能与同账号、同平台、相同数据窗口的历史内容比较。默认滚动基线为最近 90 天中位数。

表现指数由消费量、互动率和涨粉转化率组成，默认权重分别为 40%、35%、25%。缺失某项时对现有权重重新归一化；少于两项时不输出综合指数。每项相对中位数的比值限制在 0–3，最终指数以 100 表示达到基线。

收入和 ROI 不进入内容表现指数，单独显示，避免把商业化和内容影响力混成一个分数。

## 8. 分析与策略机制

### 8.1 三层输出

1. 发生了什么：描述数据和基线差异；
2. 可能为什么：列出可验证解释，并标记为假设；
3. 下一篇验证什么：一次只改变一个变量，给出主指标、护栏指标和成功标准。

### 8.2 策略证据等级

- 观察：单篇内容出现信号；
- 假设：用户或系统提出可验证解释；
- 已验证：至少三次相关实验，至少两次同向，且至少一次为预先声明的实验；
- 稳定策略：至少六次实验，跨两个时间周期，支持率不低于 70%，并已审阅反例和适用边界。

等级只是产品内的操作规则，不代表统计学因果证明。用户可以手动降级、暂停或废弃策略。

### 8.3 质量护栏

- 默认使用中位数，降低爆款异常值污染；
- 样本不足三篇时只展示观察，不输出“最佳”结论；
- 发布时间等容易受内容类型混杂的维度必须显示混杂提示；
- 同时展示支持案例和反例；
- 每项建议附带所用数据范围和缺失情况。

## 9. AI 能力

AI 是可选增强，不是产品运行依赖。

- 无 Key：生成包含必要上下文的可复制提示词；
- 有 Key：浏览器调用本地同源 API，本地服务读取环境变量并代理模型请求；
- 调用前显示准备发送的字段，默认排除客户名称、收入明细和自由文本中的敏感信息；
- 用户可以逐次勾选额外上下文；
- 优先要求结构化输出：总结、信号、风险、下一步实验和证据边界；
- 请求失败、超时、限流或结构异常时退回提示词模式；
- AI 输出只进入草稿区，用户确认后才能保存为复盘或策略；
- AI 不得修改原始指标、流水、成本和归因记录。

## 10. 飞书与表格迁移

### 10.1 支持来源

- XLSX；
- UTF-8 CSV；
- 飞书多维表导出文件；
- Matrix Compass 标准模板。

### 10.2 导入步骤

1. 选择文件；
2. 识别工作表和表头；
3. 自动建议字段映射；
4. 用户检查或调整映射；
5. 预览解析、错误、重复和关联结果；
6. 自动创建导入前备份；
7. 使用单一数据库事务写入；
8. 输出导入报告和待处理队列；
9. 允许按批次撤销。

### 10.3 当前飞书字段映射

发布记录：

- 发布序号 → `contents.external_id`；
- 平台＋账号 → 匹配或创建 `accounts`；
- 内容主题 → `contents.title`；
- 发布时间 → `contents.published_at`；
- 发布类型 → `contents.content_type`；
- 复盘 → `contents.legacy_review_note`。

收入明细：

- 发布序号 → 内容候选；
- 平台 → 账号或平台候选；
- 收入类型 → `income_entries.income_type`；
- 收入金额 → `income_entries.gross_amount`；
- 结算状态 → `income_entries.status`；
- 复盘亮点、复盘问题、优化方向 → 同名收入复盘字段。

账号概览：

- 平台、账号名称、账号定位、发布规则、选题方向、变现路径、当前粉丝量 → `accounts` 对应字段。

### 10.4 去重与关联

- 优先使用发布序号等稳定外部 ID；
- 外部 ID 缺失时使用标准化平台、账号、标题和日期生成候选；
- 完全重复可自动跳过；
- 模糊重复只能提示，不能自动删除或合并；
- 收入自动关联必须达到高置信度；
- 中低置信度进入待关联队列；
- 未映射字段保存在原始导入行中，并支持导出。

### 10.5 文件安全

- 限制文件类型、解压后体积、工作表数量、行列数量和单元格长度；
- 不执行宏、外部链接或公式；
- 导出 CSV 时处理公式注入前缀；
- 解析错误必须带工作表、行号、列名和原始值；
- 文件解析在本机完成，不上传公网。

## 11. 本地架构

### 11.1 运行组成

- 响应式 Web UI；
- 本地 Node.js 服务；
- 业务服务层；
- SQLite 持久化适配器；
- 导入、分析、备份和可选 AI 模块；
- 公网演示使用独立演示数据适配器，不访问本地 SQLite。

UI 组件和业务接口在本地正式版与公网演示版之间共享。持久化实现必须位于清晰接口之后，不能把 SQLite 调用散落在页面组件中。

### 11.2 数据目录

Windows v1 默认数据目录：

`%LOCALAPPDATA%\MatrixCompass\data\`

包含数据库、备份、导入临时文件和结构化日志。数据目录与 Git 源码、安装目录和版本标签分离。允许通过专用配置 `MATRIX_COMPASS_DATA_DIR` 指定其他绝对路径；启动时必须验证目标不是仓库根、用户主目录或磁盘根目录。

### 11.3 SQLite 要求

- 开启外键；
- 使用 WAL 模式；
- 所有批量导入和迁移使用事务；
- 数据库模式带版本号；
- 迁移必须可重复检测，不能重复执行；
- 启动时执行快速完整性检查；
- 备份恢复后执行逐表数量、外键和校验值检查。

## 12. 手机访问

### 12.1 使用方式

- 默认只监听 localhost；
- 用户在电脑端主动开启局域网访问后，服务才监听局域网地址；
- 电脑显示短时、单次使用的二维码；
- 手机扫码并确认设备名称后建立本地会话；
- 已配对设备可在电脑端查看和撤销；
- 手机使用与电脑相同的 SQLite 数据，不建立第二份本地数据库。

### 12.2 v1 安全边界

任意局域网 IP 无法天然获得浏览器受信任的 HTTPS 证书。v1 因此采用以下边界：

- 局域网访问默认关闭；
- 仅建议在受信任的家庭或办公 Wi‑Fi 使用；
- 使用短时配对码、HttpOnly 会话 Cookie、来源检查、CSRF 防护和请求版本校验；
- 不允许路由器公网映射；
- 页面明确提示局域网 HTTP 的传输边界；
- 需要加密跨网络访问时，后续单独支持经过审核的可信隧道，不在 v1 自建不受信任证书方案。

### 12.3 冲突处理

- 写入携带记录版本；
- 如果电脑端已更新同一记录，手机提交返回冲突而不是覆盖；
- 手机保留未提交草稿；
- 重连后显示字段级差异，用户选择保留版本或合并；
- 网络失败不能显示“保存成功”。

## 13. 备份、恢复与更新

### 13.1 自动备份

- 每日首次启动；
- 每次批量导入前；
- 每次数据库迁移前；
- 每次恢复操作前。

默认保留最近 7 个每日备份和 4 个每周备份。删除过期备份前必须确认至少存在一个通过校验的最新备份。

### 13.2 便携备份

备份包包含 SQLite 一致性快照、版本清单、创建时间、记录摘要和校验值。用户可选择密码加密；加密密码无法恢复，界面必须提前说明。

### 13.3 恢复

恢复前只执行预演：检查版本、记录数量、校验值和冲突。用户确认后先备份现有数据，再原子替换并执行完整性检查。检查失败时自动恢复原数据库。

### 13.4 安装 Skill

仓库提供 `skill/matrix-compass/SKILL.md`，仅负责安装、启动、更新、备份、恢复和修复，不包含用户的真实数据。

Skill 必须：

- 查询 GitHub Releases 最新稳定版本；
- 检查 Git、Node.js 22.13+ 和锁定的包管理器；
- 安装到用户确认的空目录；
- 不要求用户在聊天中发送 API Key；
- 默认使用固定本地地址，端口冲突时先说明影响；
- 更新前验证备份并检查本地源码修改；
- 更新后运行迁移、测试和数据读取验收；
- 数据异常时优先检查数据目录和数据库状态，不能以清空数据作为排错捷径。

## 14. 公网演示版

公网预览用于产品评审，必须具备完整前端交互和可验证后端健康接口，但不保存或接受真实个人数据。

- 使用脱敏种子数据；
- 显示明确“演示环境”标识；
- 导入入口只接受内置样例或在浏览器临时预览，不上传保存；
- 写操作进入可重置演示沙箱；
- 不配置真实平台密钥和用户 AI Key；
- 保持桌面端和移动端功能布局一致；
- 健康接口返回版本、数据源和服务状态。

## 15. 异常流程

### 15.1 导入错误

文件损坏、字段错误或解析失败时停止写入，显示工作表、行列和修复建议，并允许下载错误报告。

### 15.2 重复与关联冲突

并排展示候选记录，由用户选择新增、合并、跳过或暂不处理。合并前显示将改变的字段，合并后写入审计日志。

### 15.3 数据库锁定、磁盘满或进程中断

事务回滚，保留导入批次和备份，不产生半批数据。修复环境后允许从预览步骤安全重试。

### 15.4 迁移失败

停止启动新版本，恢复升级前备份，并给出迁移版本和失败原因。旧版本在数据库未被新结构写入的前提下继续可用。

### 15.5 AI 失败

超时、限流、Key 缺失和结构异常都降级到提示词模式，不阻塞内容、收入和分析功能。

## 16. 测试与质量门槛

### 16.1 自动化测试层级

- 单元测试：公式、金额精度、日期、状态机、指标字典、证据等级；
- 属性测试：随机字段、极值、Unicode、重复组合和金额不变量；
- SQLite 集成测试：外键、事务、WAL、迁移、锁定和回滚；
- 导入契约测试：XLSX/CSV、飞书样本、错误报告、撤销和原始字段保留；
- Gherkin：内容闭环、收入归因、导入、恢复、移动端冲突和 AI 降级；
- E2E：桌面、平板和手机关键流程；
- 可访问性：键盘、焦点、语义、对比度和 axe；
- 安全测试：配对、会话、CSRF、恶意文件、公式注入、秘密扫描和依赖审计；
- 变异测试：公式、导入、归因、迁移和备份模块。

### 16.2 强制阈值

- 导入、计算、迁移、备份和归因关键模块：语句与分支覆盖率 100%；
- 整体分支覆盖率不低于 90%；
- 关键模块变异得分不低于 85%；
- axe serious/critical 问题为 0；
- 关键 E2E 浏览器控制台错误为 0；
- 320px 到 1440px 关键页面无非预期横向溢出；
- 备份恢复数据差异为 0；
- 不允许通过排除关键文件、删除断言或降低阈值绕过质量门槛。

### 16.3 容量与性能

- 10,000 条内容和 30,000 个指标快照下，常用筛选、排序和分页 P95 交互不高于 200ms；
- 10,000 行 XLSX 的预览、校验、事务写入和报告生成在目标开发机上不高于 30 秒；
- 大列表必须使用服务端分页或虚拟化；
- 图表只加载当前视图需要的聚合数据；
- 移动端 20 次断网与重连演练，草稿保留率 100%，失败误报成功次数为 0。

### 16.4 对抗式场景

- 无效日期、跨时区、空值、负数、超大金额和小数精度；
- 同标题不同平台、同平台相似标题和同一外部 ID 冲突；
- 收入分配超额、零成本 ROI、零工时和取消收入；
- 文件编码、合并单元格、隐藏列、公式、宏、外部链接和压缩炸弹；
- 数据库锁定、磁盘空间不足、进程强制退出和迁移中断；
- 手机断网、重复提交、过期配对码、撤销设备和并发修改；
- AI 返回空文本、非 JSON、超长文本和越权修改建议。

任何发布候选只要有一项强制闸门失败，就不能发布稳定版本。

## 17. v1 成功标准

### 17.1 用户结果

- 用户能在不重新手录历史记录的情况下迁移飞书数据；
- 创建一条内容记录不超过 30 秒；
- 用户能在一个页面追溯内容、表现、收入、成本和复盘；
- 每周复盘能生成至少一个带证据范围的下一实验；
- 电脑和手机在同一局域网使用同一份数据；
- 更新版本不会丢失数据或要求重新导入。

### 17.2 产品质量

- 零静默数据丢失；
- 零错误自动收入归因；
- 所有派生指标可追溯到原始记录和公式；
- 所有 AI 输出可追溯到发送范围和用户确认；
- 公网预览可稳定访问且明确区分演示数据。

## 18. 实施分解

为控制风险，后续实施计划应分为以下里程碑，每个里程碑独立通过质量闸门后再进入下一阶段：

1. 本地运行骨架、SQLite、迁移、备份和安装 Skill；
2. 账号、内容、表格、详情和发布日历；
3. XLSX/CSV 导入、映射、校验、撤销和飞书迁移；
4. 指标快照、收入、成本、归因和 ROI；
5. 分析、内容实验和策略资产；
6. 手机局域网配对、冲突处理和移动端验收；
7. 可选 AI、提示词降级和隐私预览；
8. 公网演示、完整 QA、发布与回滚演练。

## 19. 已确认决策

- 用户类型：个人创作者；
- 产品骨架：内容经营实验室；
- 必备视图：表格、日历、收入和分析；
- 数据存储：电脑本地 SQLite；
- 数据录入：表单和文件导入并存；
- 历史迁移：兼容当前飞书多维表；
- 手机使用：同一局域网访问电脑数据；
- 自动平台 API：不作为 v1 核心；
- AI：可选、可降级、默认最小数据发送；
- 质量方式：对抗式审查和失败即阻断发布。
