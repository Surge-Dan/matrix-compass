# Matrix Compass 真实数据经营工作台 V2 设计规格

> 日期：2026-08-01  
> 状态：已与用户逐段确认  
> 适用范围：真实数据接入、桌面/移动端信息架构、内容与日程、收入、分析、复盘、安全和质量门禁  
> 规范优先级：本规格在冲突处覆盖 `2026-07-30-matrix-compass-creator-operations-design.md`，未冲突内容继续有效。

## 1. 产品结论

Matrix Compass 从“演示数据监控看板”升级为个人创作者的本地经营工作台。

产品必须完成一条真实闭环：

1. 从飞书、Excel/CSV 或本地表单接入真实数据；
2. 统一管理账号、内容、发布日程、收入和指标快照；
3. 从原始记录生成可追溯的经营分析；
4. 把分析转化为内容改进动作和可验证实验；
5. 在电脑和手机上使用同一份本地数据；
6. 任何导入、同步、升级和恢复都不得静默丢数。

本产品不是平台实时监控工具。v2 不依赖公众号、小红书、抖音或快手的内容平台数据接口，也不自动发布内容。飞书是迁移和只读增量数据源，Matrix Compass 逐步成为主数据源。

## 2. 已确认范围

### 2.1 必须包含

- 本地表单手动填写；
- XLSX 与 UTF-8 CSV 导入；
- 飞书自建应用 OAuth 只读连接；
- 首次全量迁移与后续增量同步；
- 账号资产、内容表格、内容日历、收入管理；
- 指标快照、经营分析、内容复盘与实验；
- 桌面端完整操作和移动端核心操作；
- 本地备份、恢复预演、导入撤销和同步审计；
- 对抗式 QA、覆盖率、Gherkin、变异测试和发布门禁。

### 2.2 明确不做

- 不申请飞书多维表格写权限；
- 不反向修改飞书数据；
- 不依赖平台抓取、模拟登录或高风险非官方接口；
- 不把本地数据库、令牌或收入明细上传到 GitHub；
- 不用演示数据冒充真实经营数据；
- 不在应用关闭时宣称后台持续同步；
- 不把 AI 建议描述为数据事实或因果结论。

## 3. 产品原则

### 3.1 真实数据优先

首次打开默认显示真实数据接入引导。演示数据只能由用户主动开启，并在所有页面持续标注“演示模式”。演示数据与正式数据库隔离。

### 3.2 一份主数据，多种视图

内容表格、日历、看板和分析读取同一组领域数据。发布日历是内容记录的视图，不复制一份“排期表”。

### 3.3 渐进式录入

创建内容的最低要求是账号、主题，以及计划时间或实际发布时间。创建收入的最低要求是关联账号、收入类型、金额和发生日期。其他字段按使用阶段逐步补充。

### 3.4 证据边界可见

每个指标、诊断和建议必须能追溯到原始记录、时间范围、样本量和计算口径。数据不足时显示“待观察”或“无法计算”，不得伪造 0、百分比或趋势。

### 3.5 本地数据主权

业务数据默认仅保存在用户指定的 Matrix Compass 数据目录中。公网演示使用隔离的演示适配器，不能访问本地数据库。

## 4. 信息架构

### 4.1 桌面端

主导航按实际工作顺序排列：

1. 经营总览；
2. 内容日历；
3. 内容库；
4. 收入管理；
5. 账号资产；
6. 复盘实验；
7. 数据导入与同步；
8. 设置。

桌面端负责完整导入、字段映射、批量编辑、复杂表格、备份恢复和权限配置。

### 4.2 移动端

底部主导航为：总览、日程、内容、收入、更多。页面常驻“快速记录”入口。

移动端主要完成：

- 快速记录内容或收入；
- 查看今天和本周日程；
- 跟进待结算项目；
- 查看账号核心指标；
- 补充内容复盘。

字段映射、批量导入、复杂列配置和恢复操作不放入移动端主流程。

### 4.3 经营总览

真实数据未连接时展示三个入口：连接飞书、导入 Excel/CSV、手动创建第一条记录。

有真实数据后展示：

- 发布内容数与账号数；
- 总收入、净收入、已结算、待结算和逾期；
- 本周日程和待处理事项；
- 经营信号、数据质量提示和同步状态；
- 可下钻的趋势与排行。

所有卡片必须使用同一筛选时间范围和可见口径，不混用全量累计与区间数据。

## 5. 数据接入架构

### 5.1 双通道统一入库

XLSX/CSV、飞书只读同步和本地表单进入相同的领域校验和持久化层。

```text
文件 / 飞书 / 本地表单
  -> 暂存与字段映射
  -> 格式校验、重复检测和关联解析
  -> 用户预览确认
  -> 单事务写入本地数据库
  -> 内容、日程、收入和分析视图
```

禁止为不同来源维护互不兼容的数据模型。

### 5.2 文件导入流程

1. 选择 XLSX 或 UTF-8 CSV；
2. 识别工作表、表头和候选数据集；
3. 自动建议字段映射；
4. 用户确认低置信度字段；
5. 预览成功、重复、冲突和错误记录；
6. 创建导入前备份；
7. 在单一数据库事务中提交；
8. 生成批次报告；
9. 允许按批次撤销。

正确行和错误行必须分别呈现。默认不允许在用户无法看见错误范围时“忽略错误继续”。

### 5.3 飞书 OAuth

推荐使用企业自建应用与用户身份 OAuth：

- 必需权限：多维表格只读；
- 持续增量同步：`offline_access`；
- Wiki 自动发现为可选能力，只在用户提供 Wiki 链接且同意额外只读权限时启用；
- 不申请多维表格写入、删除或管理权限。

凭据规则：

- App ID 可保存在普通本地配置；
- App Secret、访问令牌和刷新令牌使用 Windows 凭据保护；
- 凭据不得进入 SQLite 业务表、结构化日志、错误堆栈、备份清单或 Git；
- OAuth 回调使用随机 `state` 并限制为本机回调；
- 重新授权不得破坏已经迁移的本地数据。

### 5.4 飞书同步语义

- 首次连接：全量读取用户选定的数据表；
- 后续连接：按照源记录标识、可用的修改时间和规范化内容指纹执行增量检测；
- 应用启动时检查更新；
- 应用运行期间按配置周期检查更新；
- 用户可手动“立即同步”；
- 应用关闭时不执行同步，也不显示虚假的同步成功状态；
- 远端删除只把本地记录标记为“来源已删除”，不得自动清除本地历史；
- 本地修改与远端修改冲突时默认保留本地值，并进入字段级冲突队列；
- 每次同步保存游标、页数、新增、更新、跳过、冲突、失败和耗时。

任一分页请求失败时，本批次不得形成“部分成功但标记完成”的状态。下次同步从已确认的安全游标继续。

### 5.5 当前飞书结构映射

根据用户现有飞书截图，至少存在以下业务数据集：

#### 账号概览

| 飞书字段 | Matrix Compass 字段 |
| --- | --- |
| 平台 | `accounts.platform` |
| 账号名称 | `accounts.name` |
| 账号定位 | `accounts.positioning` |
| 发布规则 | `accounts.cadence` |
| 选题方向 | `accounts.topic_directions` |
| 变现路径 | `accounts.monetization_paths` |
| 当前粉丝量 | `accounts.current_followers` |

#### 发布记录

| 飞书字段 | Matrix Compass 字段 |
| --- | --- |
| 发布序号 | `contents.external_id` |
| 平台、账号 | 解析或匹配 `accounts` |
| 内容主题 | `contents.title` |
| 发布时间 | `contents.published_at` |
| 发布类型 | `contents.content_type` |
| 复盘 | `contents.legacy_review_note` |

#### 收入明细

| 飞书字段 | Matrix Compass 字段 |
| --- | --- |
| 发布序号 | 候选关联 `contents.external_id` |
| 平台 | 候选关联账号 |
| 收入类型 | `finance_entries.category` |
| 收入金额 | `finance_entries.amount_minor` |
| 结算状态 | `finance_entries.settlement_status` |

| 优化方向 | `finance_entries.optimization_direction` |

现有发布排期优先识别为发布记录的日历视图。若实际是独立数据表，导入预览必须先展示重复候选，不能直接复制入库。

## 6. 核心数据模型

### 6.1 `accounts`

必填字段：`id`、`platform`、`name`、`status`。

可选字段包括账号定位、发布规则、选题方向、变现路径、当前粉丝量，以及来源标识。平台内置公众号、小红书、抖音、快手、B站和其他；平台列表不得限制自定义扩展。

### 6.2 `contents`

核心字段：

- `id`：本地主键；
- `external_id`：发布序号等外部编号；
- `account_id`；
- `title`；
- `content_type`；
- `stage`：选题、创作中、待发布、已发布、已复盘、归档；
- `planned_at`；
- `published_at`；
- `url`；
- `tags`；
- `legacy_review_note`；
- 来源、版本和审计字段。

创建内容时 `title`、`account_id` 必填，且 `planned_at`、`published_at` 至少存在一个。已发布内容必须有 `published_at`。

发布日历直接查询 `contents.planned_at` 和 `contents.published_at`。v2 不用独立排期记录复制内容发布日期。非发布任务后续可使用独立任务模型，但不得与发布记录混用。

### 6.3 `finance_entries`

收入和成本采用统一财务流水：

- `direction`：income 或 expense；
- `account_id`；
- `content_id`：允许为空；
- `category`；
- `amount_minor`：最小货币单位整数；
- `currency`：v2 默认 CNY；
- `occurred_at`；
- `settlement_status`：pending、partial、settled、cancelled、overdue；
- `settled_amount_minor`；
- `expected_settlement_at`；
- `settled_at`；
- `counterparty`；
- 复盘亮点、问题、优化方向和备注。

收入与成本在界面上可分标签查看，但总账、对账和审计使用统一状态机。金额禁止使用二进制浮点累计。

### 6.4 `finance_attributions`

一笔流水可关联零篇、一篇或多篇内容。一篇内容可关联多笔流水。分配金额之和不得超过流水可分配金额；未分配部分始终显示为“未归因”。

### 6.5 `metric_snapshots`

每个快照保存账号或内容、捕获时间、指标窗口和来源。通用指标包括粉丝、曝光、阅读/播放、点赞、评论、收藏、分享、新增关注、线索、订单、完播率和平均观看时长。

新快照不得覆盖历史快照。平台特有字段保留在受控原始载荷中，并记录原字段名称。

### 6.6 `reviews`、`experiments` 与 `decision_logs`

复盘保存：表现亮点、问题、解释性假设、下一步动作、适用范围、证据和完成时间。

实验保存：目标、原始问题、单一改动变量、对照内容、主指标、护栏指标、观察周期、结果和结论。结论仅允许有效、无效或证据不足。

经营决策日志保存：决策、当时依据、适用范围、预期结果、复查时间和实际结果，形成个人经营知识库。

### 6.7 来源与审计

需要独立保存：

- 数据源与授权状态；
- 外部资源、数据表和字段映射；
- 导入/同步批次；
- 原始来源记录；
- 行级解析结果；
- 冲突及其处理结果；
- 审计日志；
- 安全游标和最近成功同步时间。

业务表不得直接承担全部同步状态，避免领域数据与连接器状态耦合。

## 7. 去重、关联与冲突

### 7.1 去重优先级

1. 数据源、资源标识与远端 `record_id`；
2. 稳定外部编号，例如发布序号；
3. 标准化账号、标题和日期构成的候选指纹。

候选指纹只能生成“疑似重复”，不得自动删除或合并。禁止仅按标题去重。

### 7.2 关联规则

收入通过发布序号、账号、平台、标题和日期分层匹配内容。只有高置信度候选可以自动关联；中低置信度进入待关联队列。

未关联收入仍是有效流水，不得丢弃或强行塞给最近一篇内容。

### 7.3 冲突策略

- 无本地修改：接受远端增量；
- 有本地修改：保留本地值并展示远端候选；
- 用户可按字段保留本地、采用远端或手动合并；
- 冲突处理保留审计记录；
- 同一远端版本重复同步必须幂等。

## 8. 核心页面交互

### 8.1 数据导入与同步

页面包含：数据源状态、连接入口、五步导入向导、字段映射、预览、冲突队列、批次历史和撤销入口。

每个批次必须展示：来源、开始/完成时间、总行数、成功、更新、重复、冲突、失败、备份和操作者。

### 8.2 内容库

默认列为状态、发布时间、平台/账号、主题、类型、阅读/播放、互动、关联收入和复盘状态。支持筛选、排序、分组、列显隐、保存视图和批量编辑。

点击记录打开详情抽屉。移动端使用内容卡片，不强行压缩完整桌面表格。

### 8.3 内容日历

提供月、周、列表视图。点击空白日期快速创建内容；只有未发布内容可拖动改期；已发布内容固定显示实际发布时间。

### 8.4 收入管理

页面包括收入概览、财务流水、待结算、成本、内容归因和收益排行。默认突出净收入、待结算和逾期，不只展示累计总收入。

### 8.5 账号资产

账号列表展示平台、名称、定位、发布规则、内容方向、变现路径、粉丝快照和经营状态。账号详情汇总其内容、收入、指标和实验。

## 9. 经营分析与内容改进

### 9.1 三层输出

1. 经营信号：发生了什么变化或异常；
2. 原因诊断：按平台、账号、内容和收入拆解；
3. 行动建议：给出下一次可验证的具体动作。

行动进入实验，结果再反馈到经营信号，形成闭环。

### 9.2 核心指标

- 内容：发布量、准时发布率、更新稳定性；
- 增长：阅读/播放、互动率、涨粉效率；
- 收入：总收入、净收入、已结算、待结算、逾期、千次消费收入；
- 风险：单平台收入集中度、单客户依赖度、长期未结算金额。

不同平台不得只比较原始播放量。比较必须同时展示账号规模、发布时间、数据窗口和样本量。

### 9.3 内容组合

按流量与收入构成高流量高收入、高流量低收入、低流量高收入和低流量低收入四类。样本不足时显示“待观察”，不强行分类。

### 9.4 智能建议

每条建议必须显示数据范围、样本数量、推理依据、建议动作和不确定性。AI 输出明确标注为“AI 建议”，先进入草稿区，用户确认后才能写入复盘或策略。

AI 不得修改原始指标、财务流水、归因和审计数据。无模型配置时产品核心功能必须完整可用，并提供可复制的结构化提示词作为降级路径。

## 10. 本地安全

- 默认只监听 `127.0.0.1`；
- 局域网访问必须由用户主动开启并完成设备配对；
- 文件限制类型、压缩后体积、工作表数、行列数和单元格长度；
- 不执行宏、公式、外部链接或嵌入脚本；
- CSV 导出防止公式注入；
- 所有批量写入使用数据库事务；
- 结构化日志执行凭据和敏感字段脱敏；
- 依赖审计与秘密扫描是发布门禁。

## 11. 备份与恢复

以下操作前必须自动备份：数据库迁移、文件导入、飞书首次全量同步和恢复。

应用运行期间每天创建备份，默认保留 7 个日备份与 4 个周备份。恢复前校验文件、版本、行数、外键和校验和，并先展示影响范围。恢复失败不得覆盖当前有效数据库。

导入批次撤销是业务级反向操作，数据库恢复是灾难恢复；两者必须在界面和实现中区分。

## 12. 异常流程

| 场景 | 必须行为 |
| --- | --- |
| 飞书授权过期 | 暂停同步，保留本地数据，提示重新授权 |
| 网络中断 | 不提交不完整分页，从安全游标继续 |
| 飞书字段改名或类型变化 | 暂停该表并要求重新映射 |
| 本地与飞书冲突 | 保留本地版本并进入冲突队列 |
| 文件部分错误 | 分离正确行和错误行，由用户决定是否提交 |
| 数据库迁移失败 | 恢复迁移前备份并维持只读诊断状态 |
| 备份损坏 | 禁止覆盖当前数据库并报告校验失败 |
| 无真实数据 | 显示接入引导，不展示演示指标 |
| AI 失败或结构异常 | 回退提示词模式，不写入业务数据 |

任何网络或磁盘失败都不得显示“保存成功”或“同步成功”。

## 13. 质量门禁

### 13.1 测试层级

- 单元测试：金额、状态机、日期、指标和证据等级；
- 属性测试：Unicode、极值、随机字段组合、金额不变量、去重幂等和分页游标；
- SQLite 集成测试：外键、事务、迁移、锁定、回滚和恢复；
- 导入契约测试：真实结构的脱敏 XLSX/CSV 与飞书响应；
- Gherkin：首次接入、增量同步、冲突、撤销、断网、恢复和移动端核心流程；
- E2E：桌面与移动端关键闭环；
- 可访问性：键盘、焦点、语义、对比度和 axe；
- 安全测试：OAuth state、凭据脱敏、恶意文件、公式注入、CSRF 和秘密扫描；
- 变异测试：导入、同步、财务、迁移、备份和恢复。

### 13.2 强制阈值

- 核心领域、导入、同步、财务计算、迁移、备份和恢复：语句、函数、行与分支覆盖率 100%；
- 其他业务代码整体分支覆盖率不低于 90%；
- 核心模块变异得分不低于 95%，全局不低于 90%；
- axe serious/critical 问题为 0；
- 关键 E2E 控制台错误和未处理请求失败为 0；
- 高危和严重依赖漏洞为 0；
- 备份恢复数据差异为 0；
- 不得通过排除关键文件、删除断言或降低阈值绕过门禁。

### 13.3 设备矩阵

- 桌面：1440×900、1366×768；
- 移动：390×844、360×800；
- 关键页面不得出现非预期横向滚动、遮挡或不可操作控件。

### 13.4 对抗式场景

必须覆盖：无效日期、跨时区、负数、超大金额、小数精度、重复标题、同外部 ID 冲突、分页重复/缺页、令牌过期、字段漂移、零成本 ROI、超额归因、隐藏列、合并单元格、宏、公式、外链、压缩炸弹、磁盘满、数据库锁、迁移中断、移动断网和重复提交。

## 14. 真实数据验收闭环

发布候选必须使用用户脱敏或授权的真实结构完成：

1. 连接飞书并识别数据表；
2. 预览账号、内容和收入映射；
3. 完成首次全量迁移并对账；
4. 新增一条远端记录并验证增量同步；
5. 在本地新增内容与收入；
6. 验证表格、日历、收入和总览一致；
7. 制造冲突并完成字段级处理；
8. 备份、修改、恢复并再次对账；
9. 在电脑和手机完成核心操作；
10. 输出稳定预览地址和质量报告。

### 14.1 预览交付

最终验收同时提供：

- 本机完整全栈地址，用于验证真实本地数据；
- 用户主动开启后的局域网地址，用于手机访问同一份本地数据；
- 持久可访问的公网演示地址，使用完全隔离的演示数据库；
- 可独立验证的后端健康检查和版本信息。

公网演示不得连接、复制或代理本地真实数据。页面必须明确标注演示数据，前端与后端需要同时可访问，不能只发布静态截图或失效的临时端口。

## 15. 实施边界

现有里程碑 0 已完成，只提供本地运行、SQLite/D1 状态、迁移、备份基础和安装 Skill，不代表业务功能已完成。

后续实施计划必须重新排序为：

1. 真实领域模型与无演示数据首页；
2. 账号、内容表格和内容日历；
3. 文件导入、预览、映射、撤销；
4. 飞书 OAuth、全量迁移和增量同步；
5. 财务流水、结算、成本和归因；
6. 指标快照、经营分析、复盘实验和决策日志；
7. 移动端核心流程和局域网配对；
8. 全量对抗式 QA、真实数据验收和稳定预览。

每个阶段必须独立通过相应质量门禁后再进入下一阶段。

## 16. 已确认决策

- 文件导入、本地表单和飞书只读同步全部需要；
- 飞书采用首次全量、后续增量、无反向写入；
- Matrix Compass 逐步成为主数据源；
- 桌面端和移动端都可用，但移动端主动做减法；
- 必须包含表格、日程、收入、经营分析和复盘实验；
- 支持公众号、小红书、抖音、快手、B站和其他平台；
- 发布日历优先由内容数据派生；
- 收入和成本使用统一财务流水；
- 演示数据不得默认冒充真实数据；
- AI 可选、可降级、证据边界必须可见；
- 数据仅在本地保存，凭据使用操作系统保护；
- 采用严格覆盖率、Gherkin、变异测试与对抗式发布门禁。
