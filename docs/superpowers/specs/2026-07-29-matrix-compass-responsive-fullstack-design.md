# 矩阵罗盘响应式全栈升级设计

日期：2026-07-29

## 1. 背景与目标

当前产品将 `public/matrix-compass.html` 作为完整应用嵌入 Next.js `iframe`。桌面端具有完整的高保真视觉，但静态页面设置了 `min-width: 1024px`，手机端主体内容被裁切；数据也仅存在于静态页面内部，没有可验证的前后端请求链路。

本次升级目标：

1. 移除 `iframe`，将界面重构为可维护的 React 组件。
2. 支持电脑、平板和手机，核心信息与操作在所有目标宽度下可用。
3. 提供真实 HTTP 演示后端，前端通过 API 获取确定性演示数据。
4. 保留现有桌面端的暖色、克制、运营工作台视觉，不进行无关重设计。
5. 建立严格、可重复、可阻断发布的质量门禁。
6. 发布到现有 Sites 项目，并验证页面和 API 的公开地址。

## 2. 范围与非目标

### 2.1 本次范围

- 数据总览页面的完整响应式重构。
- 账号管理、作品监控、粉丝分析、互动分析、异常预警和系统设置的导航与现有演示功能迁移。
- `7 / 30 / 90` 天统计周期切换。
- 加载、空数据、接口失败和重试状态。
- Dashboard API 与健康检查 API。
- 单元、组件、API、Gherkin、端到端、无障碍、覆盖率、变异和视觉回归测试。
- 生产构建、Sites 发布与外部冒烟验证。

### 2.2 非目标

- 不接入抖音、小红书、微信公众号真实开放平台。
- 不收集或存储真实账号凭证。
- 不启用 D1、R2 或其他持久化服务。
- 不将演示数据描述为真实业务数据。
- 不在本次范围内实现多人权限、计费或生产级告警通知。

## 3. 方案选择

采用 Next.js 全栈组件化方案。

未采用的方案：

- 保留 `iframe` 并补媒体查询：改动小，但无法解决组件、路由、状态、测试和后端链路割裂问题。
- 独立 SPA 加 Worker API：边界清晰，但会偏离当前 Next.js 工程，增加不必要的构建与发布复杂度。

## 4. 系统架构

### 4.1 前端

- 使用 Next.js App Router 和 React。
- `app/page.tsx` 负责页面入口，不再渲染 `iframe`。
- 页面拆分为有明确边界的组件：
  - 应用壳与响应式导航。
  - 页面标题和日期范围控制。
  - 指标卡片。
  - 趋势图。
  - 平台贡献列表。
  - 作品列表或移动端作品卡片。
  - 加载、空数据和错误状态。
- 组件只消费类型化数据，不直接持有演示数据。
- 页面通过 `fetch('/api/dashboard?range=...')` 获取数据。

### 4.2 后端

- `GET /api/dashboard?range=7|30|90` 返回仪表盘数据。
- `GET /api/health` 返回部署健康状态与应用版本。
- 数据由服务端确定性数据模块提供，不使用随机数。
- 参数校验、数据构造和响应序列化保持独立，可单元测试。
- 不依赖数据库和第三方网络服务，保证公开预览稳定。

### 4.3 数据流

1. 用户进入页面或切换统计周期。
2. 前端进入加载状态并请求 Dashboard API。
3. API 校验 `range`，读取对应确定性数据集。
4. API 返回统一结构和请求 ID。
5. 前端渲染指标、趋势、平台和作品数据。
6. 请求失败时显示明确原因与重试入口，旧数据不伪装成最新成功结果。

## 5. API 契约

### 5.1 Dashboard API

请求：

```http
GET /api/dashboard?range=30
```

成功响应：

```json
{
  "meta": {
    "range": 30,
    "updatedAt": "2026-07-29T02:32:00.000Z",
    "source": "demo",
    "requestId": "stable-request-id"
  },
  "summary": [],
  "trend": [],
  "platforms": [],
  "works": [],
  "alerts": []
}
```

约束：

- `range` 仅允许 `7`、`30`、`90`。
- 缺省值为 `30`。
- 非法值返回 `400` 和标准错误对象。
- 每个响应明确标记 `source: "demo"`。
- 数值字段使用原始数值，展示格式由前端负责。

错误响应：

```json
{
  "error": {
    "code": "INVALID_RANGE",
    "message": "统计周期仅支持 7、30 或 90 天。",
    "requestId": "request-id"
  }
}
```

### 5.2 Health API

请求：

```http
GET /api/health
```

成功响应至少包含：

- `status: "ok"`
- 应用名称与版本。
- `dataSource: "demo"`

## 6. 响应式与视觉设计

### 6.1 视觉原则

- 保留现有暖灰背景、深色导航、低饱和橙色强调和编辑感标题。
- “罗盘”作为结构性视觉语言：导航、当前范围和异常提示强调方向与定位，不额外堆叠装饰。
- 数据文本优先可读，装饰不得压过指标含义。
- 动效仅用于导航、加载和状态变化，并遵守 `prefers-reduced-motion`。

### 6.2 断点与布局

- `>= 1200px`：完整侧栏，四列指标，趋势图与平台表现并列。
- `768–1199px`：收窄侧栏，两列指标，主要分析区按可用宽度调整。
- `< 768px`：移除固定侧栏，使用顶部菜单按钮和抽屉导航；所有主要区域单列。
- 最小验收宽度为 `320px`。

### 6.3 移动端规则

- 页面不得出现横向溢出。
- 指标卡片单列或两列取决于实际可读宽度，不能裁切数字。
- 趋势图保留完整坐标与关键信息，不通过缩小文字硬塞。
- 桌面表格在手机端转换为语义完整的作品卡片。
- 抽屉、弹窗和详情面板在手机端占满可用宽度。
- 主要触控目标最小尺寸为 `44 × 44px`。

## 7. 状态与错误处理

- 首次加载：使用与最终布局一致的骨架屏，减少布局跳动。
- 周期切换：保留旧内容并标记更新中，成功后原子替换。
- 空数据：说明当前周期没有数据，并保留切换周期入口。
- API 失败：显示错误摘要、请求 ID 和“重新加载”操作。
- 非法参数：API 返回 `400`；前端不会生成非法参数。
- 演示数据：页面固定显示“演示数据”标识，避免证据边界混淆。
- 未捕获异常：错误边界提供可恢复入口，不显示空白页面。

## 8. 可访问性

- 文档语言设置为中文。
- 导航、标题、图表、表格或卡片使用正确语义。
- 所有交互均可通过键盘完成。
- 焦点样式始终可见。
- 颜色对比达到 WCAG AA。
- 图表提供文字摘要，不能只依赖颜色传递信息。
- 抽屉打开时管理焦点，关闭后焦点返回触发按钮。

## 9. 测试与质量门禁

以下门禁全部通过后才允许发布。

### 9.1 静态与构建检查

- TypeScript 严格类型检查通过。
- ESLint 零错误、零警告。
- 生产构建成功。
- Sites 构建产物校验成功。

### 9.2 自动化测试

- 单元测试：参数校验、数据转换、数值格式化和错误结构。
- 组件测试：加载、成功、空数据、失败与重试状态。
- API 契约测试：默认周期、三个合法周期、非法周期和健康检查。
- Gherkin 场景：导航、周期切换、失败重试和移动端使用。
- Playwright 端到端测试：`320 / 390 / 768 / 1024 / 1440px`。
- 无障碍自动检查与键盘路径检查。
- 视觉回归：桌面数据总览、手机数据总览和账号管理页。

### 9.3 质量指标

- 行、语句、函数覆盖率不低于 `95%`。
- 分支覆盖率不低于 `90%`。
- 核心参数校验和数据转换模块的变异测试得分不低于 `80%`。
- 所有目标宽度无横向溢出。
- 浏览器控制台无错误。
- 核心流程无失败网络请求。
- 主要触控目标不小于 `44 × 44px`。

### 9.4 对抗式 QA

- 快速连续切换统计周期，最后一次选择必须成为最终状态。
- API 返回空数组、`400`、`500` 和延迟响应时界面可恢复。
- 长标题、最大数值和中文换行不破坏布局。
- 仅键盘完成导航、周期切换、重试和关闭抽屉。
- `prefers-reduced-motion` 下不出现强制动画。
- 刷新、深色系统偏好和窄屏旋转不会导致白屏或内容丢失。

## 10. 发布与验收

1. 本地完成全部质量门禁。
2. 构建并校验 Sites 产物。
3. 发布到 `.openai/hosting.json` 中现有 Sites 项目。
4. 等待部署完成并获取公开 URL。
5. 从外部访问公开页面、Dashboard API 和 Health API。
6. 在公开地址重新执行桌面端、移动端和控制台冒烟检查。

最终交付包括：

- 可访问的公开预览链接。
- Dashboard API 和 Health API 地址。
- 桌面端、移动端截图。
- 测试与质量门禁结果。
- 明确的演示数据边界和后续真实平台接入条件。

## 11. 验收标准

- `320px` 至桌面宽度均可完成核心浏览和操作。
- 前端数据来自部署后的后端 API，而不是页面内硬编码。
- 导航、周期切换、失败重试均可工作。
- 页面明确显示演示数据属性。
- 所有阻断级质量门禁通过。
- 公开页面和两个 API 地址均返回预期结果。
- 未验证的功能或数据不得宣称为生产可用。
